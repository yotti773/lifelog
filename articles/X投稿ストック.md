# X投稿ストック(単独ポスト・再放流)

記事の公開に紐づかない、**それ単体で完結するX投稿の在庫**。書き溜めておいて、上から順に消費する。

記事公開時の告知投稿は `X投稿テンプレート.md`(本文+自己リプの型)が正で、本ファイルはその**空白期間を埋める**ためのもの。方針の背景は `README.md` の「運用ルール」を参照。

## なぜ必要か

現状、X投稿は記事を出した日にしか発生していない。週次レポート(月曜)+ ストック記事(月1〜2本の木曜)なので、**週1〜2回しか投稿していない**ことになる。フォロワー実質0の段階でこの頻度だと、そもそも認知が積み上がらない。

一方で「投稿するために記事を書く」のは本末転倒(READMEの運用ルール「減量とアプリ開発が主、記事は従」に反する)。**すでに手元にある実データ・意思決定ログ・CLAUDE.md を、記事を書かずに1投稿ぶんに切り出す**のがこのファイルの役割。

## 単独ポストの型(告知ポストとの違い)

`X投稿テンプレート.md` のルールのうち、**単独ポストでは意図的に緩めるもの**が3つある。理由込みで残す。

| ルール | 告知ポスト | 単独ポスト | 理由 |
|---|---|---|---|
| 本文に外部リンクを貼らない | 必須 | **そもそもリンクが無い** | 単独ポストはリーチのペナルティが構造的に無い。ここが最大の利点で、実験的な文面を試す場としても向く |
| 画像を1枚付ける | 必須 | **流用が効くときだけ** | 1日1本のペースで全部に画像を作ると運用が破綻する。各投稿のメタ欄に流用可能な既存画像を書いてある |
| アプリ名「からだログ」を毎回入れる | 必須 | **週1本でよい** | 30本すべてに「体重と食事を記録する自作PWA『からだログ』の〜」を入れると定型句がうるさく、読み味が死ぬ。代わりにカテゴリAとCは自然にアプリ名が入る文面にしてあるので、**Bだけが連続しないよう順番で担保する**(下記の消費ルール) |

緩めないもの(告知ポストと共通):

- ハッシュタグは1〜2個
- 先頭1行は具体・数字・痛み・結果のどれか
- 付いた反応には全部返信する
- 読者層を混ぜない(技術ネタの自己リプに減量noteをぶら下げない、など)

## カテゴリ

- **A. 実データ系**(12本) — スプレッドシートの実データから作る「信じている数字が違う」型。想定読者は増減量サイクルを回す層+個人開発クラスタ。note06(実測TDEE)・需要検証2本目3本目と同じ鉱脈なので、**記事公開前に同じ数字をXで出しすぎない**よう、記事の公開日近辺では温存する
- **B. 開発の小ネタ**(14本) — 意思決定ログ・CLAUDE.md から拾う技術/判断の1ネタ。想定読者はエンジニア層。`X投稿テンプレート.md` の記入例で確認済みの「**gotchaより判断から入るほうが射程が広い**」に従い、gotcha系と判断系を混ぜてある
- **C. 既存記事の再放流**(8本) — 公開済みのnote/Zenn 5本+別プロジェクト1本を、**公開時とは別の切り口・別の画像**で再投稿する。C-08だけは固定ポスト候補

## 消費と補充のルール

- **1日1本まで。連投しない。** 在庫があると一気に出したくなるが、タイムラインを占有すると逆効果
- **カテゴリを日替わりでローテーションする**(A → B → C → A …)。読者層が違うので、同じカテゴリが3日続くと片方が飽きる。あわせて、この順番を守ればB(アプリ名の入らない技術ネタ)が2日以上続かないため、上記「週1本でよい」が自動的に満たされる
- **消費したらメタ欄の `使用日` を埋める。** 同じ文面を二度出さない。行は消さずに残す(何が伸びたかを後から見るため)
- **数字には消費期限がある。** カテゴリAの数値は 2026-08-05 時点の実データ(2026-05-18〜08-02の77日間)。週次レビュー由来の数字(必要ペース・着地予測)は毎週変わるので、**投稿前にアプリの週次レビュー画面で最新値に差し替える**。該当する投稿にはメタ欄に `要更新` と書いてある
- **補充の湧き口**: `docs/からだログ_意思決定ログ.md`(特に「対応不要としてクローズ」した判断は、やったことより強い)・`CLAUDE.md` の「注意点」「〜しないこと」系の記述・週次レビュー画面の実データ・Issueのクローズ理由

## 数字の出どころ

カテゴリAの数値はすべて、同期用スプレッドシート「からだログ」の実データ(2026-05-18〜2026-08-02の77日間)を 2026-08-05 に集計したもの。詳細な検算は `note06_実測TDEE_下書き.md` の「データの出どころと検算」節が正。

| 数値 | 値 | 使っている投稿 |
|---|---|---|
| 期間・記録数 | 77日間(体重93日分・食事80日分・Garmin活動92日分) | A-01, A-06 |
| 週平均体重の変化 | 73.53kg → 71.04kg = −2.49kg | A-01, A-10 |
| 平均摂取カロリー | 1,961kcal/日 | (背景) |
| 全期間の逆算TDEE | 2,210kcal/日 | A-09 |
| Garmin総消費 平均 | 2,857kcal/日 | A-01, A-09, A-11 |
| Garmin活動消費 / 安静時相当 | 862kcal/日 / 1,994kcal/日 | A-11 |
| Garminとの乖離 | 647kcal/日 → 77日で6.5kg分 | A-02, A-09 |
| 「その数字が正しければ」の到達点 | Garmin 9.0kg / 実際 2.49kg = 3.6倍 | A-01, A-10 |
| 週次逆算値(13週) | 最小1,572 / 最大3,447 / 標準偏差530 | A-04 |
| 停滞2週(6/15〜6/28) | +0.36kg、摂取2,198kcal/日(+121)、歩数18,064歩(+1,100)、記録14/14日 | A-03 |
| 対象期間の食事記録率 | 76/77日 | A-06 |

**計算式TDEE(約2,335kcal/日)だけは導出値**で、設定画面の実値ではない(目標カロリーと必要日次赤字からの逆算)。A-09 で「約2,300」と丸めて使っているが、**投稿前に設定画面の実値を確認すること**。

週次レビュー由来の数値(必要ペース−0.55kg/週、直近実績−0.41kg/週、着地予測68.0kg)は**7/27週時点**のもので毎週変わる。A-08・C-06 は投稿前にアプリの週次レビュー画面で最新値へ差し替える。
