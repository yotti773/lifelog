## 全体コンセプト

「個人開発で食事記録アプリを作った」ではなく、次の3本柱で書く:

1. **開発プロセス**: 仕様書駆動 + AIエージェント(Claude Code)で個人開発を回す実例
2. **設計の中身**: ローカルファースト、決定論的計算+AI言語化の分業、壊れる前提の外部連携
3. **n=1の物語**: 自作アプリで自分を計測し、10/31までに72kg→64kgを目指す減量実験(実データ付き)

### note記事2(週次レポート)の定型フォーマット(2026-08-04改訂)

毎週の執筆コストを抑えつつ、**他人が持ち帰れるものを1つは必ず入れる**ための固定枠。改訂の経緯は進捗ログの2026-08-04を参照。数字とAIコーチの出力は素材であって記事ではない、というのが改訂の要点。

1. **今週の1行** — 体重がどう動いて、何が分かったか。結論を先頭に置く
2. **今週わかったこと(1つだけ)** — 記事の主役。次のいずれかから1つ選ぶ:
   - その週の開発トピック(仕様の判断と理由)
   - データから読み取れた発見(実測TDEEとGarmin実測消費の乖離、睡眠×摂取カロリーのクロス分析など)
   - 記録・運用そのものの判断(入力コストの設計、続いた/続かなかった理由)

   **アプリのコミットが無い週でも省略しない。** 7/20週・7/27週は「開発トピックが無い」を理由に丸ごと省いたが、乖離データのような素材は実際にはあった(7/27週は実測TDEE 1,895kcal に対しGarmin実測消費 3,222kcal で1,300kcal超の乖離、7/20週も1,861 vs 2,628)。コミットの有無と「書けることの有無」は別。
3. **今週の数字** — 5〜6行に圧縮する。週平均体重・前週比・平均摂取kcal・実測TDEE・記録率が基本で、PFCや参考値(歩数・睡眠・水分・血圧)は2の話に絡む時だけ出す
4. **AIコーチはこう言った / 自分はこう読んだ** — 引用は3〜4行に切り、**自分の解釈を引用と同量以上**書く。納得いかなかった点・自分の読みと違った点を書くとAIコーチの精度検証になり、読み物になる。全文引用はしない
5. **リンク** — アプリ(https://lifelog.n1lab.workers.dev/)・GitHub(https://github.com/yotti773/lifelog)・関連するZenn記事・前回の週次レポート。**毎回必ず入れる**(note02〜04は導線がゼロだった)

**分量の目安**: AI引用+数字リストが本文の半分を超えたら、自分の言葉が足りていない。改訂前の3本は実測で58〜65%だった(note02 58% / note03 65% / note04 63%)。

**タイトル**: 「週次実験レポート(日付)」を先頭に置かない。スマホの一覧は冒頭25字前後で切れるため、**その25字だけで主張が立つ**ようにし、日付は末尾か本文冒頭へ回す。長さは20〜25字を目安にする(35字を超えると、面白い後半が確実に切れる)。

**ハッシュタグ**: `#個人開発` を先頭に、`#ClaudeCode` を必ず入れる(note01にしか付いていなかった)。`#ダイエット記録` `#減量` は外さず後ろに置く — 想定読者は個人開発クラスタだが、n=1の減量実験であること自体は記事の芯なので捨てない。noteのカテゴリ設定も「ライフスタイル > ダイエット・フィットネス」から開発寄りに合わせる。

## 画像(サムネイル・記事中の図)の作り方

記事のサムネイル・図・X投稿用画像は、HTML/CSSで組んでPlaywrightでPNGに書き出す。配色はアプリのデザイントークン(クリーム `#FFF8F0` / プライマリ `#FF6B4A` / ティール `#2EC4B6`)に合わせる。**アクセントのサニーイエロー `#FFC145` は「達成の瞬間」専用のため、記事画像でも常時表示の要素には使わない**(デザインガイドの制約)。正確な値は `docs/からだログ_デザインガイド.md` のカラーパレット表と `src/theme.ts` が正。

- **X投稿用の画像には、右下に「丸型アイコン+ハンドル(@yotti073)」の署名を入れる**(2026-08-03決定)。Xのアイコンと同じ絵が画像内にあると、タイムライン上で「この人の投稿だ」と認識されやすい。アイコン素材は `プロフィールアイコン.png`(元の緑背景のまま正方形に切り出したもの)。**キャラだけを切り抜いて大きく配置する案は「浮いて見える」ため却下した**(2026-08-03、本人判断)— 背景を抜いたキャラを本文の横に置くと、貼り付けたステッカーのように見えて画面から浮く。小さく署名として置くほうが意図的に見える。**noteのサムネイルには入れない**(同日決定。noteは記事の顔なので数字と見出しに集中させる)
- **既定フォントは M PLUS Rounded 1c(丸ゴシック)。** note記事1のサムネイルがこれで、シリーズの見た目をここに揃える(2026-08-02決定)。見出しは800、本文は400〜700。コード・IDなど等幅にしたい箇所だけmonospaceを使う。例外として `note03_サムネ.png` だけは Zen Kaku Gothic New(角ゴシック)で作ってあり、これは当時の判断のまま残す
- **Google Fontsをレンダリング環境から直接読めない場合がある。** ヘッドレスChromiumから `fonts.googleapis.com` に到達できず、CSSの指定が無視されてシステムのゴシックに**黙ってフォールバックする**(エラーにならないので気づきにくい)。`curl` は通るので、Google Fontsの `text=` サブセット機能で必要な文字だけのwoff2を取得し、base64で `@font-face` に埋め込んでからレンダリングする。書き出し後は `document.fonts.size` が0でないことを必ず確認する
- **上下に間延びした余白を作らない。** キャンバスを `grid-template-rows: auto auto 1fr auto`(ヘッダー/見出し/本体/フッター)で組み、本体のカードを `align-items: stretch`、中の行を `flex: 1` で伸ばして高さを埋める。中身が薄くて埋まらない場合は、余白を足すのではなく**情報を足す**(コード1行を添える、対になる事例をもう1行足す等)か、キャンバスの縦を詰める
