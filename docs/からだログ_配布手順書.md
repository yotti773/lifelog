# からだログ 配布手順書

作成日: 2026-08-23(Issue #246。配布版 #213 の実装完了を受けて)
関連: #213(配布版)・#218(トークン運用)・#219(AIへの同意)・#238(プライバシーポリシー)

## これは何か

**数人にアプリを使ってもらうときの手順**をまとめたもの。配る側の準備と、受け取る人に送る案内文を持つ。

前提として、次はすでに済んでいる(2026-08-23):

- 本番URL https://lifelog.n1lab.workers.dev/ に配布版がデプロイ済み
- OAuth同意画面が**本番公開済み**(テストユーザーの登録は不要。refresh tokenの7日失効も無い)
- Workerのシークレット `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET` 登録済み

## 1. 配る側の準備

### 1.1 相手ごとにAPIトークンを発行する

**1人1本の別々のトークンを渡す。** 同じ値を配ると、1人だけ止めることができなくなる(#218)。

```bash
# 十分な長さのランダム値を作る(1人分)
openssl rand -base64 32
```

PowerShellしか無い場合:

```powershell
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Max 256 }))
```

### 1.2 Workerのシークレットに追加する

Cloudflare ダッシュボード → Workers & Pages → **lifelog** → Settings → Variables and Secrets → `API_AUTH_TOKEN` を **Edit**。

**既存の値を消さずに、カンマ区切りで足す**:

```
(自分のトークン),(Aさんのトークン),(Bさんのトークン)
```

> **空にしないこと。** シークレットが在るのに有効なトークンが0本だと、Workerは全リクエストを拒否する(全開放よりは安全側に倒す設計。#218)。

### 1.3 誰にどれを渡したかを控える

**リポジトリにもIssueにも書かない。** 手元のパスワードマネージャ等で管理する。止めたい相手が出たときに、どの1本を外せばよいかが分かればよい。

### 1.4 渡すもの

| 渡すもの | 値 |
|---|---|
| URL | https://lifelog.n1lab.workers.dev/ |
| APIトークン | 1.1 で作った、その人の1本 |
| プライバシーポリシー | https://lifelog.n1lab.workers.dev/privacy |

## 2. 相手に送る案内文(そのまま使える)

> **からだログを使ってみてください**
>
> 体重・食事・水分・筋トレ・日記を記録して、週ごとに振り返るアプリです。スマホのブラウザで開いて使います。
>
> **1. 開く**
> https://lifelog.n1lab.workers.dev/
> スマホなら「ホーム画面に追加」しておくとアプリのように使えます(iPhoneは共有ボタン → ホーム画面に追加、Androidはメニュー → アプリをインストール)。
>
> **2. 目標を入れる**
> 最初に目標体重・目標日・1日の目標カロリーを聞かれます。決めていなければ「あとで設定する」で飛ばせます。
>
> **3. 合言葉を入れる**
> 設定タブ → 「API保護」→ APIトークン に、別に送る文字列を貼り付けて保存してください。AIの判定機能を使うために必要です。
>
> **4. Googleと連携する**
> 設定タブ → 「Googleアカウント」→ 「Googleと連携する」。
> 途中で「**確認されていないアプリ**」という警告が出ますが、個人が作ったアプリのため出るもので、故障ではありません。「詳細」→「(安全ではないページ)に移動」で進んでください。
> このアプリが求める権限は「**このアプリが作成したファイルへのアクセス**」だけです。あなたのDriveにある他のファイルは見えません。
>
> **5. 記録の保存先を作る**
> 設定タブ → 「同期先シート」→ 「スプレッドシートを作成」。
> **あなた自身のGoogle Drive**に「からだログ 記録」というスプレッドシートが作られ、以後の記録はそこに保存されます。私(配布者)からは中身を見られません。
>
> **6. 使ってみる**
> ホームから体重や食事を記録してください。記録はまず端末の中に保存され、上のシートへ自動で同期されます。
>
> **AIの機能について**
> 食事の写真判定と週次コメントの生成では、GoogleのGemini APIに写真や記録の要約が送られます。初回に確認のダイアログが出るので、内容を読んで決めてください。**同意しなくても記録・グラフ・同期はすべて使えます。**
> 詳しくは https://lifelog.n1lab.workers.dev/privacy
>
> **困ったら**
> 動かない・分からないときは連絡してください。

## 3. 説明しておくこと

案内文に含めてあるが、口頭で聞かれたときのために要点を挙げる。

- **記録はその人の端末(ブラウザ)の中に保存され、同期を有効にするとその人自身のGoogle Driveのスプレッドシートに入る。** 配布者のサーバーには保存されない(#215)
- **Googleに要求する権限は `drive.file` だけ。** アプリが作成したファイル以外にはアクセスできない(#214)
- **AIに送られるもの**: 食事の写真・入力テキスト、記録の要約、日記の気分タグ。**日記の本文は既定で送らない**(設定でONにしたときだけ)。同意しなければAI機能だけが止まる(#219)
- **Garmin連携は付いてこない。** 「活動」タブは空のままになる(歩数・睡眠は配布者本人の環境だけの機能)
- **アクセス解析・広告・第三者提供は無い**(#238)

## 4. 止めたいとき

Cloudflareの `API_AUTH_TOKEN` から**その人の1本だけを外す**。他の人は影響を受けない。

外した相手のアプリは、AI機能とGoogle連携のトークン更新が401になる。**記録・グラフはそのまま使えて、記録も消えない**(端末とその人のシートにある)。

## 5. 起こりうるトラブル

| 相手が見る表示 | 原因 | 対処 |
|---|---|---|
| 認証に失敗しました。設定画面のAPIトークンが… | APIトークンが未入力・打ち間違い | 設定 → API保護 で貼り直す(前後の空白に注意) |
| Googleの連携設定を取得できませんでした | 同上(連携の入口でも同じ認証を通るため) | 同上 |
| 確認されていないアプリ | 非機微スコープのまま公開しているため常に出る | 「詳細」→「移動」で進む(故障ではない) |
| アクセスをブロック: …審査プロセスを完了していません | 同意画面が「テスト中」に戻っている | Google Cloud Console の公開ステータスを確認する |
| 同期先のスプレッドシートがありません | シート未作成 | 設定 → 同期先シート → スプレッドシートを作成 |
| 「活動」タブに記録がありません | Garmin連携は配布に含まれない | 仕様。文言の改善は #245 |

## 6. 費用について(配布者向け)

AI機能(食事判定・週次/月次コメント)は**配布者のGemini APIキーで動く**ため、使われるぶんの費用は配布者持ちになる。数人であれば軽量モデルの料金で収まるが、**人数を増やすときは費用と、レート制限(#244)の要否を見直すこと**。

## 7. 継続率の測定について

#213 は当初「4週間後に3人以上が週4日以上記録していれば継続の目安」という合格基準を置いていた。しかし **#215 で記録が各自のDriveへ直接入るようになり、配布者からは記録が一切見えなくなった**(設計としてはそれが目的)。

**測定は行わない**という判断をした(2026-08-23)。相手にスクリーンショットや記録日数の報告を求めることはせず、使ってもらった感想と、使い続けているかどうかの体感で判断する。**数値の合格判定は降ろす。**

- シートを閲覧者として共有してもらう案は採らない — 他人の健康データを見ることになり、「記録はお預かりしません」という配布の前提と食い違う
- 利用状況のテレメトリを送る案も採らない — プライバシーポリシー(#238)に「アクセス解析は行いません」と書いた直後に入れることになる
