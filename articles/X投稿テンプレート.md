# X投稿テンプレート(本文+自己リプで伸ばす)

記事(note/Zenn)を出したときのX投稿の型。インプ(表示)を伸ばすための固定フォーマット。毎回ここを開いてスロット(`{ }`)を埋めて使う。方針の背景は `README.md` の「運用ルール」を参照。

## 基本原則(なぜこの型か)

- **本文は単体で完結した価値にする。外部リンク(note/Zenn)は本文に貼らず、自己リプ(返信)に回す。** Xは外部リンクのある投稿のリーチを下げるため。
- **ハッシュタグは1〜2個まで。** Xではタグはほぼリーチに効かず、多用は宣伝臭くて逆効果。
- **画像を1枚付ける**(週次サムネ・グラフ・コードのbefore/afterスクショなど)。滞在時間が伸びて拡散されやすい。
- **付いた反応(リプ・引用)には全部返信する。** 会話がいちばん評価される。リンクを撒くより会話で伸ばす。

## 投稿の型(3段)

1. **本投稿**: 【フック1行】+【中身2〜4行】+【画像】+【#タグ1〜2】
2. **自己リプ①**: 記事リンク(「詳細/続きはこちら👇」+ URL)
3. **自己リプ②(任意)**: シリーズの背景 or 前回記事へのリンク(初見の人を過去記事へ誘導)

### フック1行の作り方

先頭に**具体・数字・痛み・結果**のどれかを置く。1行目でスクロールを止められないと以降は読まれない。

- 悪い例: 「ブログ書きました」「週次レポート更新しました」
- 良い例: 「新規ユーザーだけ永久ローディングになる罠にハマった」「はじめの1週間、体重は−0.23kg動いた」

## 記事タイプ別テンプレ

### A. note(週次レポート・一般向け)

本投稿:

```
自作アプリで減量実験、今週の結果です📊

{今週の一番の数字。例: 週平均 −0.23kg / 記録率100% / 連続78日}
{一言の所感 or AIコーチ判定。例: AIコーチには「やや遅れ」と言われつつ}

10/31まで−8kg、淡々と。
#個人開発
```

画像: その週の週次サムネ(`note0N_サムネ.png`)

自己リプ①:

```
詳しい数字とAIコーチのコメントはこちら👇
{note記事URL}
```

自己リプ②(任意・初見向けの背景導線):

```
そもそもなぜ健康管理アプリを自作したのか、という背景はこちら👇
https://note.com/yotti073/n/n54d80318b1d8
```

### B. Zenn(技術記事・エンジニア向け)

本投稿:

```
{技術的な痛み/gotchaを1行。例: 開発中は自分のブラウザにデータがあるから絶対踏まないけど、新規ユーザーだけ永久ローディングになる罠がある}

{2〜3行で中身の要点。数字や固有名詞(Dexie/useLiveQueryなど)を入れる}

原因と対処をZennに書きました。
#個人開発
```

画像: コードのbefore/after(❌/✅)スクショ1枚

自己リプ①:

```
記事はこちら👇
{Zenn記事URL}
```

自己リプ②(任意・シリーズ導線):

```
開発の進め方(仕様書駆動 × Claude Code)はこちら👇
https://zenn.dev/yotti073/articles/spec-driven-claude-code
```

### C. 記事なしの開発ログ投稿(意思決定ログ由来)

記事の公開に紐づかない単発の投稿。`docs/からだログ_意思決定ログ.md` に書き足した決定・検討の1エントリを、そのままネタにする。**エントリが増えるたびに素材が増える**ので、記事を出さない週の在庫として使える。

**A・Bより意識的に柔らかく書く。** A・Bは「読ませて記事に送る」ための緊張が要るが、C型は送り先が無く着地点がないため、同じ強さで書くと教訓の押し付けになる。具体的には:

- **です・ます調に寄せる**(A・Bは常体でよい)。常体だと1文ごとに言い切りが立ち、開発ログには強すぎる
- **オチの断定を外す**(「〜だった」→「〜だったのかも」)。結論の提示ではなく発見の共有として置く
- **独り言寄りの語尾(「〜んですよね」など)を1つ入れる。** リプライしやすい温度になる
- **本文は4行程度に収める。** 記事に送らないぶん情報量で押す理由がなく、長いと説教くさくなる

ただし**1行目の具体性は緩めない**(緩めるとスクロールが止まらない)。柔らかくするのは2行目以降。

本投稿:

```
{気づき・判断を1行。具体を落とさない}

体重と食事を記録する自作PWA「からだログ」。
{2行で中身。断定を外す}

{オチ1行。「〜かも」で止める}
#個人開発
```

画像: その回の主張が1枚で完結する対比図など(A・Bと同じく署名入り)

自己リプ①: 新規記事が無いため、内容に一番近い既存記事へ回す

自己リプ②: A・Bと同じレーン導線

## 記入例: Zenn記事3(Google Sheets同期エンジン)

上のBテンプレを実際に埋めたもの。フックの作り方・画像との噛み合わせの参考に。

本投稿(画像: `zenn03_X画像_upsert.png`):

```
個人開発のDB、Google Sheetsで十分だった。
ただし追記だけで同期すると必ず壊れる。

体重と食事を記録する自作PWA「からだログ」のバックアップ先の話。
編集で行が重複し、削除はシートに残り続ける。
ID列でupsertに倒すと解決。

Cloudflare Workersでの実装をZennに書きました。
#個人開発
```

自己リプ①:

```
記事はこちら👇
https://zenn.dev/yotti073/articles/cloudflare-workers-google-sheets-sync
```

自己リプ②:

```
このアプリ、10/31までに−8kgを目標に自分を実験台にしながら作っています。
同じアプリの「保存」側の話(Dexie + useLiveQueryでローカルファースト)はこちら👇
https://zenn.dev/yotti073/articles/dexie-uselivequery-pitfalls
```

このとき考えたこと:

- **フックは「技術的なgotcha」より「判断」から入るほうが射程が広い。** 当初は「上から順に消すと別の行が消える」という削除順序のgotchaを1行目に置いていたが、これはSheets APIを触っている人にしか刺さらない。「スプレッドシートで十分だった」という**判断**を先に出すと、まだ触っていない層まで拾える。技術の深さは2文目以降で担保する
- **画像の見出しはフックと同じ主張にする。** 画像が技術説明だけだと、1行目の面白い部分が絵の中に無く、フックと絵が噛み合わない。画像側も「主張(黒)→どんでん返し(オレンジ)→根拠(カード2枚)」の3段にして、**画像単体でフックが完結する**ようにした
- **本文と画像で表記を割ってよい。** 本文は「Google Sheets」(検索・専門性)、画像は「スプレッドシート」(読みやすさ)と使い分けている
- **アプリ名「からだログ」と、それが何かを必ず1行で入れる。** 技術記事の投稿は放っておくと技術詳細だけになり、初見の人が「誰が何を作っている人なのか」を掴めないまま流れていく。本文に「体重と食事を記録する自作PWA「からだログ」の〜」を1行、自己リプ②に「10/31までに−8kg、自分を実験台に」を1行入れて、**発信のレーン(自作アプリで自分を人体実験している個人開発者)を毎回必ず通す**。技術だけの投稿は他の人と差がつかず、プロフィールに来てもフォローの理由にならない。**名前を出さずに「自作アプリ」とだけ書くのも不足** — 毎回名前を出すから、回を重ねたときに「からだログの人」として認識が積み上がる
- **ボツにした画像も捨てない。** 削除順序の図(`zenn03_X画像_行削除順序.png`)は、公開1〜2週間後に切り口を変えて同じ記事を再放流するときに使う

## 記入例: note記事4(週次レポート・7/27週)

上のAテンプレを実際に埋めたもの。週次レポート回の参考に。

本投稿(画像: `note04_X画像.png`):

```
先週より−0.41kg。減ってはいる。
でも「このままだと届かない」とアプリに言われた。

体重と食事を記録する自作PWA「からだログ」の週次レビュー。
残り89日、必要ペースは−0.55kg/週。
着地予測68.0kg(目標64.0kg)。

減ってるのに足りない、が数字で見える。
#個人開発
```

自己リプ①:

```
今週の数字とAIコーチのコメントはこちら👇
https://note.com/yotti073/n/ne4a3440999ef
```

自己リプ②:

```
10/31までに−8kg、自分を実験台にアプリを作りながら減量中です。
そもそもなぜ健康管理アプリを自作したのか、という背景はこちら👇
https://note.com/yotti073/n/n54d80318b1d8
```

このとき考えたこと:

- **週次レポート回のフックは「良い数字」で終わらせず、その直後に反転を置く。** 「−0.41kg減った」だけだと自慢で終わって読む理由が無い。「減ってはいる。でも届かない」と**減ったのに足りない**という緊張を1〜2行目で作ると、続きを読む動機になる。数字が良かった週でも悪かった週でも、この「事実→反転」の型は使い回せる
- **X画像は週次サムネの流用ではなく、専用に作った。** テンプレの既定はnoteサムネの流用だが、noteサムネは4行の数値カードが主役でタイムライン上(特にモバイル)では小さくて読めない。X画像は16:9(1200×670)で、**見出し2行+数値カード3枚(必要ペース/今週の実績/着地予測)**に絞り、文字を大きくした。「必要ペース−0.55 vs 実績−0.41」と並べることで、本文を読まなくても画像だけで「届いていない」が伝わる
- **画像の右下に「丸型アイコン+@yotti073」の署名を入れる(2026-08-03、本人提案)。** Xのアイコンと同じ絵が画像内にあると、タイムラインで「この人の投稿だ」と認識されやすくなる。素材は `プロフィールアイコン.png`(元の緑背景のまま正方形に切り出したもの。CSSで `border-radius:50%` にして使う)。**最初はキャラだけを背景透過で切り抜き、見出しの横に大きく置いたが「浮いて見える」ため却下した** — 背景を抜いたキャラを本文の横に配置すると貼り付けたステッカーのように見え、レイアウトから浮く。小さく署名として置くほうが意図的に見え、ハンドルも一緒に露出できる

## 記入例: 開発ログ(AIコメントは復元できない・2026-08-03)

上のCテンプレを実際に埋めたもの。記事に紐づかない単発回の参考に。素材は同日の意思決定ログのエントリ(発展方向の検討で判明した、週次・月次AIコメントが復元されない問題。#164)。

本投稿:

```
自作アプリのバックアップ、AIのコメントだけ戻ってこないことに気づきました。

体重と食事を記録する自作PWA「からだログ」。
数値は計算し直せるけど、AIコーチの文面は毎回変わるので、消えたら終わりなんですよね。

記録より、記録への"評価"のほうが貴重だったのかも。
#個人開発
```

自己リプ①:

```
そもそもこのアプリ、仕様書とClaude Codeでどう作ってるかはこちら👇
https://zenn.dev/yotti073/articles/spec-driven-claude-code
```

自己リプ②:

```
10/31までに−8kg、自分を実験台にアプリを作りながら減量中です。
なぜ健康管理アプリを自作したのか、という背景はこちら👇
https://note.com/yotti073/n/n54d80318b1d8
```

このとき考えたこと:

- **ネタは「判断」より「発見」を選んだ。** 同じ日の検討からは「案を5つ出して2つをやらないで潰した」という判断側のネタも取れたが、そちらは中身が抽象論で終わり、読んだ人が持ち帰れるものが無い。「LLMの生成物はバックアップ対象として特殊(数値と違って再現できない)」は**他の人のプロジェクトにも移植できる発見**なので、こちらを採った。C型は記事に送らないぶん、本文単体で持ち帰れるものがあるかがそのまま価値になる
- **推敲の順序は「柔らかく → 短く → オチを戻す」だった。** 最初の案は常体で言い切りが強く、開発ログとしては説教くさかった。柔らかくした結果あちこち冗長になったので中盤の説明を削り、最後に一度落としたオチを戻した。**削るのは中盤の説明、残すのは1行目とオチ** — この2つが投稿の価値をほぼ決める
- **オチは「〜かもしれません」ではなく「〜かも」で止めた。** 丁寧に伸ばすと文が重くなり、4行に収めたぶんの軽さが消える。です・ます調に寄せるのは本文で、オチは短く切るほうが余韻が残る

## 記入例: 開発ログ(次に何を作るか決めた日・2026-08-03)

**上の記入例と同じ日の検討から取った2本目。** 1本目が「発見」(AIコメントは復元できない)なのに対し、こちらは「状況・判断」を切り口にしている。C型は意思決定ログの1エントリから複数の角度が取れるため、**日を空けて小出しにする**。

本投稿:

```
毎日使えていて不満もない。個人開発でいちばん困るのがこの状態なんですよね。

体重と食事を記録する自作PWA「からだログ」、作りたい機能が尽きたので
今日はコードを書かず、次に何を作るかだけ決めました。

「やらない」を2つ書き残せたのが、いちばんの進捗かも。
#個人開発
```

自己リプ①②: 1本目と同じ(仕様書駆動のZenn記事 → 自作した背景のnote記事)

このとき考えたこと:

- **同じ日に2本続けて出さない。** 初速が分散して両方とも埋もれる。1本目を出した2〜3日後に回す。意思決定ログを在庫として使うC型は、**ネタが余るからこそ小出しの間隔を守れる**のが利点
- **「成果」をそのまま書かない。** 当初は「Issueを9つ立てて2つ閉じた」を1行目に置いていたが、これは自分のTODO報告で読んだ人が持ち帰るものが無い。テンプレ冒頭の悪い例(「ブログ書きました」)と同じ構造。**同じ材料でも「不満なく使えているアプリの次を決める日」という状況に置き換えると、共感の射程が出る**
- **1行目は「事実 → 反転」にした**(note04回で効いた型の流用)。「不満もない」→「だからいちばん困る」と1行の中で反転させると、続きを読む動機になる。良い状態を報告して終わらせない
- **件数を並べるのはやめ、数字はオチの「2つ」だけに寄せた。** 9件・2件・PR2本…と並べると報告の見た目になる。数字は1つに絞るほうが効く

## 投稿前後のチェックリスト

- [ ] 投稿はフォロワーが起きている時間(平日 朝7〜9時 / 昼 / 夜21〜23時)。技術記事は平日朝が伸びやすい。
- [ ] 投稿の15〜30分前に、同じ界隈の他人のポストへリプして自分を温める(初速が付きやすい)。
- [ ] 本文にURLを入れていない(リンクは自己リプに回した)。
- [ ] ハッシュタグは1〜2個。
- [ ] 画像を1枚付けた。
- [ ] フック1行が「具体・数字・痛み・結果」のどれかになっている。
- [ ] **アプリ名「からだログ」と、それが何かが1行入っている**(初見の人が読んでも、体重・食事を記録する自作PWAの話だと分かる)。「自作アプリ」とだけ書いて名前を落としていないか。
- [ ] 画像の右下に「丸型アイコン(`プロフィールアイコン.png`)+@yotti073」の署名が入っている(タイムラインでの認識性のため)。
- [ ] 読者層で混ぜていない(一般向けnoteの投稿にエンジニア向けZenn記事をぶら下げない、など)。
- [ ] **記事なしのC型なら、A・Bより柔らかい温度になっている**(です・ます調、オチの断定を外す、本文4行程度)。1行目の具体性だけは緩めていないか。
- [ ] 投稿後、付いた反応には全部返信して会話を続ける。

## 発信のレーン(軸)

「**自作アプリで自分を人体実験している個人開発者**」(開発 × 減量 × AI × 実データ)という掛け算で一貫させる。bio・固定ポストもこの軸に揃えると、プロフィールに来た人がフォローしやすい。

## 補足: 過去投稿への後追いリプについて

すでに投稿して時間が経った(=初速の終わった)ポストに、あとから自己リプでリンクを足しても、届くのは「スレッドを開いた人」だけで表示数は伸びにくい。**永久的な導線としては足す価値があるが、伸びは期待しすぎない。** 次回からは本投稿と同時に自己リプまで一気に組んで、最初からスレッドにするのが伸びる形。
